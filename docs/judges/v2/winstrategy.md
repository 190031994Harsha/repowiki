# Judge v2: winstrategy (x-ai/grok-4.6)
_2026-08-31 12:15 UTC_

**It wins if a judge can *use* the wiki like a staff-engineer brief, then *audit* a claim in one click, then watch the system *delete its own sentence* rather than ship a fake cite.** Everything else in this field is fluent markdown. You already built the only architecture that can make silence a feature. You have not yet staged that as a single artifact.

## What you have that the RAG/wrapper field does not

They will all emit Overview / Architecture / Modules with `[file.py](…)` links and a table that says “grounded.” You have a **closed citation algebra**:

1. LLM is forbidden from writing line numbers.
2. It may only emit `[[sym:qual.name]]` or a path the index already knows.
3. A deterministic resolver binds the span or the sentence dies.
4. A second pass re-validates the *emitted* wiki, not the prompt’s intentions.
5. Trajectories record repair, drop, cost, and the exact prompt.

That is not a better prompt. It is a type system for claims. Wrappers cannot copy it in 24h because they have no symbol index, no fail-closed renderer, and no honest “we dropped the sentence” log.

You also have something rare in this genre: **you already published the regressions** (click validity 0.96→0.78, fastapi module coverage 0.50→0.04, httpx/packaging readability → 0.00, claim-support 0.74 not 1.00). Most of the field will hide those. Judges who have been burned by leaderboard theater will *start* trusting you — then they will open a wiki. That second moment is where you currently lose.

## What the winner will have that you still don’t

Not more pages. Not another eval column. Three things:

- **A product surface, not a pipeline.** The field’s README is a lab notebook. The winner’s README is a *thing you open*. Judges screenshot UI, not `evals/report.md`.
- **Meaning, not coordinates, in the demo path.** You still mostly prove “this span exists.” 0.74 claim-support on 75 sampled sentences is an appendix. The winner makes *one page* where every visible claim is visibly supported, and the unsupported ones are gone — in the artifact, not in a JSON file.
- **A surprise that is true.** The winner’s wiki teaches the judge something about a repo they already know (Flask request context, Requests adapters, FastAPI dependency injection) that official docs bury — *and the citation is the punchline.* Right now your punchline is the harness. Harnesses don’t win.

Landmines a first-prize judge will poke in 90 seconds: fastapi `module_coverage 0.04`, readability 0.00 pages, click validity regression, and any live wiki that still reads like “dense citation sludge.” Honesty notes do not save a bad page.

## The one remaining move (~24h)

**Ship one self-contained HTML “receipt” of a repo every judge already knows (Flask or Requests — not FastAPI), with three panes that no wrapper can fake.**

Not a new model. Not 10 more repos. Not another metric. One file, e.g. `showcase/flask.html` (or `requests`), generated by the advanced pipeline, that is the entire demo.

### What it contains

1. **The wiki page itself** — Overview + one architecture slice + one module deep-dive. Prose a human would keep. Citations are the *only* links.
2. **Click/hover a citation → the actual source lines inlined** (the 8–40 lines the resolver bound, with `file:start-end` and a GitHub permalink). No navigation, no clone, no 404. The judge never leaves the file.
3. **A “Grounding ledger” and a “What we refused to say” appendix**  
   - Ledger: `claim → span → supports?` for every sentence on that page (reuse your claim-support judge; this page only, 100% of claims, not a 75-claim sample across repos).  
   - Refused: the exact sentences the repair loop **dropped**, with the unresolved `[[sym:…]]` and `claims_dropped` from the trajectory. Fail-closed on camera.

That is the move because it converts your unique machinery into a **screenshot**, and it is unavailable to RAG wrappers: they cannot show a resolver bind, and they cannot show a dropped claim without admitting they hallucinate.

Do **not** spend the 24h on: more models, embeddings, FastAPI coverage theater, fixing readability’s sentence splitter globally, or another 12-repo sweep. Optionally, if the HTML lands early, add a 20-line `repowiki drift` that re-resolves the same ledger against a second commit and lists claims that went invalid. That is the encore, not the act.

## Demo moment / one-liner / screenshot

- **One-liner:** “A wiki that would rather delete a sentence than underline a lie.”
- **Demo (30s):** Open `showcase/flask.html` → scroll to a non-obvious claim (“`Flask` is a class, not a module; request context is pushed in `…`”) → click the cite → source lines appear, highlighted → scroll to **What we refused to say** → a fluent sentence is struck through because `[[sym:flask.Foo]]` never existed.
- **The screenshot:** that one HTML frame: prose + inline source popover + a red “dropped” row in the ledger. That image *is* the submission. Put it at the top of the README. If a judge cannot get that moment without running a 448s pipeline, you do not have a demo.

Secondary artifact worth 10 minutes: a 12-second GIF of the same click, committed next to the HTML, so even a tired reviewer sees it.

You do not beat the field by being a better doc generator. You beat it by making **refusal inspectable**. The cite-by-symbol loop is the only original invention in the bundle; the next 24 hours exist to make one judge say they have never seen a documentation tool *throw work away on purpose*, with the source still on screen.
